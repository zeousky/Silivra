# Silivra

An independent AI project combining **its own language model and tokenizer trained
from scratch**, a local assistant runtime, coding and research tools, and durable
private memory. All model inference uses Silivra's original model lineage. External
model weights, tokenizers and hosted model fallbacks are unsupported.

```sh
uv sync --locked
uv run silivra
# Select an existing own-model checkpoint explicitly:
uv run silivra --model runs/silivra-assistant-v2
```

Model weights stay local and are excluded from Git. Cloning the source repository
does not download a trained model. Training commands below initialize or continue
Silivra checkpoints and never provision a replacement model.

## Original-model research

**Original-model research status: active early development.** The original 14M checkpoint learns English story completion. The project includes an interactive CLI, tool-capable assistant runtime, scoped memory, instruction tuning and assistant evaluation. The v2 run completed 8,000 updates: instruction loss improved, but independent task accuracy remained 0/15 and story-language loss regressed. **The original model is not a reliable general or coding assistant.** See [v2 results](docs/ASSISTANT_V2_RESULTS.md), [earlier capability results](docs/CAPABILITY_RESULTS.md), [architecture](docs/ARCHITECTURE.md), and the [long-term roadmap](docs/ROADMAP.md). The model lineage uses no external weights or tokenizer. TinyStories text was generated by upstream language models; the protocol fixtures are explicitly labeled AI-assisted.

Public source: [zeousky/Silivra](https://github.com/zeousky/Silivra). Code is MIT; weights, private chats, memory databases and raw datasets are excluded from this repository.

The [latest quality experiments](docs/QUALITY_RESULTS.md) test focused instruction
learning and rehearsal while preserving the original model/tokenizer. The runtime
now replays validated conversation roles in training format, saving 35% of prompt
tokens on the measured follow-up fixture. Narrow training can teach greetings
while damaging broader skills, so task accuracy and retention are measured before
any default checkpoint change. Passing tests or valid JSON alone is insufficient.
Both focused and rehearsal runs failed the overall acceptance checks; v2 remains the original-model default. All 214 local tests passed at that milestone, while
broad learned assistant competence remains unfulfilled.

The [native English v5 experiment](docs/NATIVE_ENGLISH_RESULTS.md) made real
weight updates to the original model. Narrow shared-template accuracy improved
from 5/94 to 31/94, while broader diagnostics stayed 3/85 and earlier language
and instruction losses regressed. V5 remains an explicitly selectable experiment;
robust English explanations, arithmetic, coding and model-directed search are
still unreliable. The general default remains v2.

## Interactive terminal

```sh
uv sync --locked
uv run silivra --model runs/silivra-assistant-v2
```

The terminal loads your local checkpoint on the first ordinary message. `/help`
lists commands; `/models`, `/model PATH`, `/new`, `/sessions`, and `/resume ID`
manage checkpoints and conversations. `/tool read_file {"path":"pyproject.toml"}`
executes an explicit workspace read. `/memory remember language This project uses Python.`
saves a durable fact only at your request. `/exit` quits.

Start with `/tools none` for plain conversation, or select a focused tool with
`/tools read_file`. Writes, network and command execution each need an explicit
permission grant for the current process. Preferences and input history stay in
ignored private `.silivra/` state. Streaming answers are labelled as drafts until
their complete JSON action validates. See the [terminal guide](docs/CLI.md) for
multiline input, cancellation, settings, permissions, memory and direct tools.

Weights remain local: cloning this public repository does not include model
weights. Inference requires an existing local Silivra checkpoint. Passing runtime
tests does not establish learned model skill.

## Coding and research tools

After `uv sync --locked`, tools work independently of whether the model has learned to choose them:

```sh
uv run silivra tools
uv run silivra tool read_file --arguments '{"path":"pyproject.toml"}'
uv run silivra tool search_files --arguments '{"query":"TODO","path":"src"}'
uv run silivra tool web_search --allow-network --arguments '{"query":"Python asyncio documentation","limit":3}'
uv run silivra tool web_fetch --allow-network --arguments '{"url":"https://docs.python.org/3/library/asyncio.html"}'
```

Eight tools cover bounded arithmetic, workspace listing/reading/search, guarded file writes, command execution, web search, and public HTTPS fetching. `calculate` interprets a small arithmetic AST without executing code; it reports exact rational calculations as decimal text, with rounding labelled at 50 significant digits. Writes require `--allow-write`; an existing file additionally requires its current full `expected_sha256` from `read_file`. Network requires `--allow-network`. Broad web search uses an optional exported `BRAVE_SEARCH_API_KEY`; without a key, results explicitly report Wikipedia encyclopedia coverage. `.env` files are not automatically loaded.

`--allow-exec` enables trusted local argv execution, with time/output limits and a stripped environment. **This runs as your OS user and is not a sandbox.** Commands can access host files and network beyond file-tool restrictions. Leave it disabled unless you trust the model and workspace, or run Silivra inside an external sandbox.

## Private memory

```sh
uv run silivra memory remember language "This project uses Python." --category preference
uv run silivra memory recall "project language"
uv run silivra memory revisions language
uv run silivra memory sessions
uv run silivra memory export --output .silivra/my-memory.json
uv run silivra memory backup --output .silivra/backup.sqlite
uv run silivra memory forget language
```

Memory is stored in ignored `.silivra/memory.sqlite`, scoped by the selected workspace and `--user` label. For another project, place `--workspace PATH` and `--user LABEL` immediately after `memory`. Facts retain provenance, revisions, confidence and importance; FTS5 retrieval considers lexical relevance, importance and recency. Sessions retain scoped user/assistant/tool history. Use `memory history SESSION` and `memory delete-session SESSION` to inspect or erase a transcript.

Durable facts require explicit `remember`; web results and model guesses are never automatically saved as facts or training data. Forgetting a key removes its revisions/search entry, while separate transcripts and old backups remain until deleted. JSON exports contain one scope; SQLite backups contain all scopes. Obvious credentials are rejected/redacted, but do not use the store as a secret vault. See [memory design](docs/ARCHITECTURE.md#memory).

## Train and evaluate assistant behavior

The instruction pipeline starts from a verified local checkpoint and writes a separate run. The included original examples are a protocol/pipeline fixture, **not a broad coding or knowledge dataset**.

```sh
uv run silivra prepare-instructions \
  --train examples/instructions/train.jsonl --valid examples/instructions/valid.jsonl \
  --tokenizer data/tinystories/tokenizer.json --output data/instructions-smoke
uv run silivra finetune --data data/instructions-smoke --base runs/silivra-tiny \
  --run runs/silivra-instruct-smoke --config configs/finetune-smoke.json --max-minutes 2
uv run silivra evaluate-assistant --run runs/silivra-instruct-smoke
uv run silivra chat --run runs/silivra-instruct-smoke --no-tools --memory-chars 0 "Say hello."
```

`chat` accepts an optional prompt or opens an interactive session. Use `--session ID` to resume, `/new` for a fresh session, and repeat `--tool NAME` to expose selected tools. One-shot chat defaults to no tools; interactive chat honors saved selections. `--no-tools` explicitly disables all model tools. `--all-tools` is available for sufficiently long-context checkpoints. `--allow-network`, `--allow-write`, and `--allow-exec` still gate permissions. Its native backend demands strict JSON actions and stops visibly when a checkpoint cannot follow the protocol. The entire policy, request, tool definitions and output reservation must fit context; the initial 512-token window needs short requests, focused tools and sometimes `--max-new-tokens 64`. Multi-step observations quickly exhaust this window. Context failure is reported explicitly.

Instruction loss masks out prompts/tool results. Preparation rejects exact conversation and normalized user-prompt overlap across train/validation, and records licensing/source hashes. See [training instructions](docs/TRAINING.md). Genuine general ability still needs broader licensed pretraining, more instruction data, longer-context training and held-out task evidence.

The original procedural curriculum provides 400 training and 100 separate validation exercises for literal instructions, elementary arithmetic, Python basics, and single-tool proposals. Generate it with `uv run python scripts/build-curriculum.py --output data/curriculum-v1 --tokenizer data/tinystories/tokenizer.json`, then follow the [curriculum training recipe](docs/TRAINING.md#procedural-capability-curriculum). Its narrow results are reported separately from general capability.

## Run locally

Requirements: Apple silicon Mac, 16 GB or more unified memory, **macOS 26 or later for the pinned MLX Metal 0.32.4 wheel**, and [uv](https://docs.astral.sh/uv/). Tested on an M4 MacBook Air with 16 GB, macOS 27.0.1, and Python 3.12. The runtime uses the Metal GPU; it does not use the Neural Engine. Other Apple chips have not yet been tested.

```sh
uv sync --locked
uv run silivra doctor

# Download bounded public text subsets and train a NEW tokenizer locally.
uv run silivra prepare

# Initialize random weights; train for at most 15 minutes in this session.
uv run silivra train --config configs/m4-16gb.json --max-minutes 15

# Reload the exact optimizer, scheduler, data sampler, and RNG state if interrupted.
uv run silivra train --resume --max-minutes 15

uv run silivra generate "Once upon a time, a little fox"
uv run silivra evaluate
uv run silivra benchmark --output runs/silivra-tiny/benchmark.json
uv run silivra export --archive
```

Dependency setup and corpus preparation explicitly download their respective public artifacts. Training and model inference then run offline; model prompts stay on your Mac. There are no hosted model calls or telemetry. Optional network tools send search queries or URLs only when enabled; Brave can use an optional key. `uv run --offline silivra generate "Once upon a time"` uses the existing environment without checking the package index.

The working checkpoint is already present locally after the initial test run in `runs/silivra-tiny/`. These large generated artifacts are excluded from Git. `best.json` and `latest.json` select complete checkpoints; each checkpoint includes a `model.safetensors`, original `tokenizer.json`, architecture and training settings, dataset manifest, optimizer/RNG state, and file hashes. Generation defaults to the best measured validation checkpoint. An explicit checkpoint directory also works with `--run`.

`Ctrl-C` requests a checkpoint at the next completed training step. The session timer covers the training loop; data checks, initialization, baseline evaluation, final evaluation, and checkpoint writes add time. Resume preserves the original total step count and learning-rate schedule. Once all configured steps have finished, `--resume` performs no additional updates. Choose a longer schedule in a new run for a larger initial experiment.

For a short pipeline check in a separate run:

```sh
uv run silivra train --run runs/smoke --config configs/smoke.json --max-minutes 1
uv run silivra generate --run runs/smoke "Once upon a time"
uv run python -m unittest discover -s tests -v
```

## The 16 GB design

| Component | Initial configuration |
| --- | --- |
| Learned parameters | 14,162,304 |
| Decoder | 8 layers, width 384, SwiGLU intermediate width 1,024 |
| Attention | 6 query heads, 2 key/value heads, fused Metal attention |
| Positions and normalization | RoPE and RMSNorm |
| Tokenizer | 4,096-token byte-level BPE, trained on the selected training text |
| Embedding and output | One tied weight matrix |
| Precision | FP32 training and weights |
| Training context | 256 tokens; 16 sequences per step |
| Maximum inference context | 512 tokens; quality beyond training length is unverified |
| First schedule | 2,500 AdamW steps, 10,240,000 token exposures |

The model implements established transformer components directly in MLX. Grouped-query attention and chunked KV storage reduce inference memory. Training reads CPU memory-mapped uint16 token streams and transfers only the current minibatch to MLX. Generation resets and recomputes the trailing window when the context fills, rather than retaining an invalid cache.

The default original-model training budget is 6 GiB, with a 256 MiB allocator-cache guideline. **MLX's memory limit is advisory, not a hard system cap.** The trainer checks peak MLX allocations between steps and checkpoints when its budget is exceeded. macOS, other apps, and allocations within a step can still use additional memory. The benchmark reports MLX allocation and process RSS separately; neither number is total system RAM usage. No swap, system security, sysctl, or global Python packages are changed.

The weights encode language; they are not inherently restricted to Apple hardware. The implementation, profiling target, memory policy, and training workflow are Apple-specific. There is no measured claim of an architectural advantage over other small models.

## Training data and evaluation

The default preparer takes 30,000 unique complete stories from the pinned official TinyStories training split and 1,000 from its separate validation split. It trains BPE only on training text and excludes exact normalized story overlap across splits. Downloads stop at complete story delimiters, subject to a 128 MiB training and 32 MiB validation transfer ceiling. Larger requests may hit that ceiling; they never silently download the full multi-gigabyte corpus.

The manifest records the upstream revision, original URLs, source-prefix hashes, selected story counts, duplicates skipped, tokenizer version/hash, and token-stream hashes. This is a prefix sample, not a representative random sample of the entire corpus. Validation measures next-token loss on a fixed reproducible sample; it is not an assistant or coding benchmark.
