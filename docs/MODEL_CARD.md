# Silivra Tiny — model card

**Release stage:** local experimental pretraining checkpoint, version 0.1.

This card describes the preserved original base. The separate
[assistant v2 experiment](ASSISTANT_V2_RESULTS.md) completed 8,000 instruction
updates with the same parameter/tokenizer lineage and 1,024-token context. It
remains unreliable on independent assistant tasks. Its mixed instruction-data
licenses and weight-distribution review are separate from this base designation;
no v2 weights or datasets are published in the source repository.

**Purpose:** a reproducible language-model training and inference foundation for Apple silicon MacBooks with 16 GB unified memory. The first experiment learns simple English story continuation. It is initialized from random parameters and uses a tokenizer trained from scratch. There is no pretrained checkpoint, distillation loss, adapter, or inherited model tokenizer.

**Architecture:** causal decoder with 14,162,304 learned parameters; 8 layers; width 384; RMSNorm; RoPE; SwiGLU; 6 query/2 KV heads; tied embedding/output weights; 4,096-token byte-level BPE; 512-token configured inference window. The initial training length is 256 tokens. The original implementation uses MLX and Metal with FP32 weights and AdamW.

**Training data:** 30,000 unique TinyStories training stories and 1,000 separate official validation stories. TinyStories is synthetic text generated by upstream GPT-3.5/GPT-4 models and made available under CDLA-Sharing-1.0. Original parameter initialization does not mean that the training text is human-authored. The tokenizer never sees validation text during fitting. Exact SHA256-based overlap is excluded; near-duplicate overlap is not assessed.

**Training and results:** see [INITIAL_RESULTS.md](INITIAL_RESULTS.md). Local `runs/silivra-tiny/run.json`, `summary.json`, `metrics.jsonl`, `benchmark.json`, and each checkpoint's `state.json` are the machine-readable evidence. Validation samples are fixed by seed. There is no external test set, general capability benchmark, safety evaluation, M1/M2/M3 validation, or comparison with an equally trained baseline yet.

**Intended use:** local research, educational inspection, architecture/memory experiments, and experimental story completion. Generation can be nonsensical, repetitive, biased, or inappropriate even when loss improves. It does not reliably follow instructions, answer facts, solve arithmetic, or write code. It is unsuitable for decisions requiring correctness. The separate assistant runtime can expose tools through strict JSON actions and explicit permissions; the original checkpoint has not learned reliable tool use. See [CAPABILITY_RESULTS.md](CAPABILITY_RESULTS.md) for native assistant diagnostics and subsequent instruction experiments.

**Hardware claims:** tested only on the user's 16 GB M4 MacBook Air. FP32 weights alone occupy 56,649,216 bytes before serialization metadata. Peak MLX allocation, process RSS, and total machine memory are different measurements. MLX memory limits are guidelines. Inference uses the GPU rather than the Neural Engine. Benchmark speed uses warm kernels, a fixed story prompt, greedy fixed-length generation, and suppression of EOS for timing; it excludes model loading. Actual prompts, thermal state, and power mode can change speed.

**Reproducibility:** architecture/training configs, seed, AdamW state, NumPy/MLX RNG state, exact tokenizer, immutable corpus revision, artifact hashes, and dependency lock are recorded. A small regression test checks that interrupted/resumed training matches uninterrupted training exactly on the tested MLX version. Exact results across different Apple hardware or MLX versions are not guaranteed.
