# Assistant quality experiments — 2026-10-22/23

The original model and tokenizer are preserved. These experiments improve the
training/evaluation workflow and test whether short native fine-tuning produces a
better assistant. They do not establish general intelligence or reliable coding.
The default must pass the explicit regression checks before being changed.

## Runtime improvement

Completed conversation turns now use the same user/assistant/tool roles as
training. The previous runtime wrapped each past message inside another user
message, increasing escaping and changing the learned format. A representative
follow-up uses 212 tokens instead of 326 with the unchanged original tokenizer.
This 35% reduction preserves more usable history within the context budget.
Complete turns are trimmed together. Parsed past actions are inert; interrupted,
malformed and orphaned turns are omitted, and prior content cannot grant tools or
introduce a system message. Dedicated runtime tests cover those boundaries.

The bare `silivra` launcher was installed locally and verified from the home
directory. The [terminal guide](CLI.md) provides a reproducible installation.

## Focused v3: useful narrow learning, rejected overall

The separate v3 run started from verified v2 step 8,000 with the unchanged
14,162,304-parameter model and 4,096-token tokenizer. It trained 2,000 updates
in 278.995 seconds, using at most 1.470 GiB of MLX allocations. This is not total
system RAM. Best fixed validation loss selected step 1,200; later steps overfit.
The final step remains separately available with optimizer/sampler/RNG state.

The original Codex-authored MIT curriculum has 2,041 training and 216 validation
conversations. It covers greetings, identity/limitations, native two-turn history,
copying, supplied facts, single-digit addition/comparison and Python print output.
Names, copied words and ordered numeric pairs are split before generation. These
are narrow shared-template tasks. Validation loss is not a broad quality score.

| Measure | v2 step 8,000 | v3 selected step 1,200 |
| --- | ---: | ---: |
| Historical diagnostic exact successes | 0/6 | 1/6 |
| Earlier independent diagnostic exact successes | 0/15 | 0/15 |
| Practical quality-v1 successes | 3/40 | 1/40 |
| Full synthetic validation successes | 14/216 | 84/216 |
| Synthetic validation loss, fixed comparison sample | 1.09327 | 0.97132 |
| Prior v2 instruction validation loss | 2.98620 | 7.55119 |
| Original unseen story validation loss | 3.06644 | 5.55725 |

A native two-turn Agent probe returned `Hello! How can I help you?` for `hi`, and
`I'm here and ready to help. How can I help you?` for `how are you`. Those responses
are generated by the trained original model, without canned-answer routing or a
hosted fallback. The second wording is absent from quality-v1's frozen finite
accepted alternatives, so it fails that automated case despite being relevant.
The suite was kept unchanged. Other unrelated responses still fail correctly.

Synthetic gains include addition 0/30 to 12/30, comparison 14/30 to 24/30,
conversation 0/12 to 10/12, supplied facts 0/64 to 32/64 and Python output 0/15 to
5/15. Exact copying remains 0/64. Broad factual, memory, coding and tool failures
remain. The severe retention losses outweigh the narrow gains, so v3 is experimental
and was not promoted to the default.

[Full comparison](results/quality-v3-comparison.json) and
[training/provenance record](results/quality-v3-training.json) retain hashes and
bounded public diagnostic generations. They exclude imported corpus rows, private
chats, memory databases, machine paths and model weights.

## Rehearsal v4

A second experiment mixes the 2,041 core examples with 1,000 Dolly records,
800 balanced original v2 exercises and 200 original-training stories. Its 344
validation records include all 216 core cases and 128 earlier validation records.
Original source licenses and attributions are retained. The run starts separately
from unchanged v2, with 2,000 updates, batch four, learning rate 0.0001 and a
6 GiB advisory MLX allocation budget. Its approved loop budget is 20 minutes.

Promotion required maintaining the existing quality-v1 score, maintaining the
fresh quality-v2 baseline, coherent native greetings, and both prior instruction
and original story loss within 5% of v2. Checkpoints were selected by fixed joint
validation loss, not diagnostic task scores.

The original process stopped after logging step 700, with a complete checkpoint
at step 400. Resume restored its optimizer, scheduler, sampler and RNG state;
unsaved steps were replayed and original logs preserved. The run completed all
2,000 updates. Saved cumulative training time is 313.582 seconds, excluding lost
unsaved updates; peak MLX allocation is 3.389 GiB. Step 1,200 was selected. The
training sampler's joint validation loss rose from 2.64622 to its selected 2.76625.

| Measure, unchanged comparison settings | v2 step 8,000 | v4 selected step 1,200 |
| --- | ---: | ---: |
| Historical diagnostic exact successes | 0/6 | 0/6 |
| Earlier independent diagnostic exact successes | 0/15 | 0/15 |
| Practical quality-v1 successes | 3/40 | 2/40 |
| Fresh practical quality-v2 successes | 0/24 | 0/24 |
| Full synthetic validation successes | 14/216 | 30/216 |
| Mixed instruction validation loss, comparison sample | 2.72024 | 2.82200 |
| Prior v2 instruction validation loss | 2.98620 | 3.16461 |
| Original unseen story validation loss | 3.06644 | 3.30030 |

Prior instruction loss worsened 5.97% and story loss 7.62%, exceeding the 5%
limits. Practical accuracy also fell. V4 is therefore rejected as a default.
The smaller regression versus v3 does not make it a successful general assistant.
[Full comparison](results/quality-v4-comparison.json) and
[training/provenance](results/quality-v4-training.json) preserve the evidence.

## Weight-average recovery check: rejected

A final low-cost check averaged every matching v2/v4 weight as
`(1-alpha) * v2 + alpha * selected_v4`, using the fixed grid 0.25, 0.5 and 0.75.
This makes no gradient updates and uses no external weights. All three met the
retention-loss limits. Lowest core validation loss selected alpha 0.75 before
checking generated answers. Its core loss was 0.57657, prior instruction loss
3.08135 and story loss 3.20039. Those validation sets were used for selection;
these numbers cannot also be claimed as independent improvement evidence.

Generated answers still failed: quality-v1 remained 2/40, quality-v2 0/24, and a
native `hi`/`how are you` probe produced an unrelated response followed by an
invalid action. No averaged checkpoint was promoted or substituted in the runtime.
[Grid, selected diagnostics and native probe](results/quality-weight-average.json)
show why favorable loss numbers alone were insufficient.

## Delivered state

The default remains v2; original checkpoints, tokenizer and private data are
preserved. V3/v4 are local, explicitly selectable experiments. The reliable
improvements are validated training-format history, complete-turn context
trimming, usable command installation, deterministic licensed data/replay
preparation and stricter evidence for accepting or rejecting model changes.
All 214 local tests pass, including native MLX numerical tests and portable
runtime/data tests. No new Linux CI run or live network/provider test is claimed.
No inference is delegated to a pretrained or hosted replacement. General
reasoning, coding, grounding, tool choice and memory interpretation remain poor.
Further short fine-tuning on these same fixtures is not supported by these results;
broader original-model pretraining and genuinely broader instruction competence
remain unfulfilled research milestones.

## Evaluation boundaries

The 40-case [quality-v1](../examples/evaluations/quality-v1.md) and fresh 24-case
[quality-v2](../examples/evaluations/quality-v2.md) suites cover conversation,
instructions, elementary reasoning, grounding, Python, tools, supplied memory and
honesty. Their prompts were authored independently of training data and their
answers frozen before native outputs. Quality-v1 informed the rehearsal experiment
and is consequently a development diagnostic for v4. Quality-v2 was authored by
a separate agent without access to curricula, datasets, earlier fixtures or outputs.

The four diagnostic suites have zero exact normalized user-prefix overlap with
current training. V4 also excludes them from its selection validation. This does
not rule out semantic/template overlap or all pretraining contamination. Two of
the 216 synthetic cases have prior v2 training exposure; their IDs are disclosed
in comparison metadata. They remain held out from the current training mix.

Exact parsed actions grade constrained tasks; explicit finite whole-answer
alternatives grade selected prose cases. This is not a semantic judge. Proposed
tools and Python solutions are never executed; memory is supplied fixture data,
not a storage/retrieval benchmark. Language and instruction losses have different
masking and cannot be compared numerically to each other. V3 and v4 validation
mixtures differ, so compare each run with its own baseline and use the unchanged
prior-v2/story samples for cross-run retention.
